## 一、项目需求（我们要解决什么）

### 1.1 赛题本质（竞赛主线）

- **任务**：AI4S 智能体 CNS 挑战赛 — **蛋白质构象系综生成**（任务 3）。给定 `document/1.json`、`2.json`、`3.json` 中的**氨基酸序列**（单链），预测其在溶液中可及的**多构象代表集**（每题最多 10 个），而非单一静态结构。
- **交付物**：
  - `output.zip`：标准 **mmCIF**（`{problem_id}_conf{N}_pred.cif`）+ **`agent.log`**（研发全流程可追溯，缺失可取消成绩）。
  - 体积 ≤ 100MB；每 CIF 须**全原子坐标**、无 NaN/Inf、可解析。
- **评分（初赛）**：`Total = 0.5 × Base Score + 0.5 × Ensemble Quality`  
  - **Base**：GT 与 Pred 的 CA-RMSD，Coverage + Precision（双向最近邻）。  
  - **Ensemble**：多样性（RMSF、pairwise RMSD）、PCA 覆盖、clash/Ramachandran、Boltzmann 一致性等。
- **合规红线**（`document/rull.md`）：**不得**使用本次赛题私有 GT、GT ensemble、原始 MD 轨迹；**可以**使用公开 PDB、AlphaFold DB、公开预训练模型（ColabFold/AF/ESMFold/Chai/Boltz 等）及基于**题目序列**的预测。

### 1.2 科研原型需求（工程验证主线）

对话早期按 `readme.md` 规划，并行搭建了一条**可复现的计算生物学 MVP**：

- **OpenMM**：溶剂化、最小化、NVT/NPT，产出 `traj.dcd`。
- **MSM**：特征（CA 距离/二面角）→ PCA/tICA → 聚类 → 转移矩阵、ITS、CK、PCCA-like、MFPT、`auto_summary`（可直接写周报）。
- **智能体工作流**：文献/Prompt 套件、分步决策（冒烟 → 短程 → 1 ns → 参数优化）、`daima/YYYYMMDDHHMM` 归档。

### 1.3 过程性约束（用户/仓库规则）

- `document/` 为原始设定，**未经同意不改**。
- 实时代码在仓库根目录；每次可能改变线上分数的运行，将**相关代码 + 参赛结果**归档到 `daima/YYYYMMDDHHMM`。
- 优化要求：**小步迭代**、在 `readme.md` §1.5 留痕、有灵感写入提分路线；**先本地评测再线上 A/B**。

## 二、项目整体思路（怎么做的）

### 2.1 双轨架构

```text
                    ┌─────────────────────────────────────┐
                    │     document/1,2,3.json（序列）      │
                    └─────────────────┬───────────────────┘
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
   公开数据准备                  序列条件预测                   模板/几何管线
 prepare_public_data.py    ColabFold / Boltz / Chai      RCSB 同源 CIF + template_align
 (RCSB 序列检索)            → results/colabfold/...       / template_cif / hybrid 全原子
          │                           │                           │
          └───────────────────────────┼───────────────────────────┘
                                      ▼
              build_sequence_prior_sources.py（长度、pLDDT、多源合并、截断）
                                      ▼
              generate_submission.py（diversity_filter、侧链修复/避碰、mmCIF 导出）
                                      ▼
              output.zip + agent.log + local_eval.json
                                      ▼
              archive_run.py → daima/YYYYMMDDHHMM（可复现快照）
```

**竞赛侧核心判断**：涨分主杠杆是 **Base Score（序列相关的多样、高质量构象）**，而不是在固定模板池上无限调 `diversity_filter` 或侧链网格参数。

**科研侧核心判断**：MSM 质量依赖**采样时长 + 聚类粒度**；短轨迹只能验证流程，不能当科学结论。

- **决策点显式化**：环境（pip/conda）、示例蛋白、MD 时长档位（冒烟/短程/1 ns）、MSM 参数（P1/P1.5/S1/R）均由用户选字母，避免 agent 擅自长跑。

## 三、项目中遇到的问题（踩坑清单）

### 3.1 提交与评测

| 问题 | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 首提 **0 分** | 排行榜无有效分 | 仅 CA 骨架、mmCIF 不完整、几何不合理 | 全原子导出；精确模板用 `mdtraj`；`template_align` 避免共线 CA |
| **fast-preview 崩盘** | 0.537（较 0.70 **−0.16**） | `single_sequence`、pLDDT≈29 的 PDB 进入 `prefer_sequence_prior` | 默认 **`--min-mean-plddt 50`**；预览仅验证管线，不默认冲榜 |
| P1 diversity 加大无效 | 0.695（multiplier 3） | 候选池未变，只增几何扰动 → precision 受损 | **multiplier 回退 2**；改候选来源而非只调筛选 |
| 平台期「改了不涨分」 | 0.700651 多次相同 | 侧链轮数 3→4 等只改本地 clash proxy | 确认主杠杆在 **序列条件候选**，非 hybrid 微调 |

### 3.2 OpenMM / MSM（科研线）

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| 冒烟轨迹过短 | `n_frames=15`，CK=poor | 先证明流程；再 0.2 ns → 1 ns → 1.5 ns |
| **NaN 坐标** | 2 ns、`dt=0.004` 时 NPT 崩溃 | **`step_size_ps` 改为 0.002**；或缩短目标时长 |
| 宏观态塌缩 | 单态占比 ~1.0 | **`n_clusters` 50→20→15**；延长采样 |
| CK 仍标 poor | `auto_summary` 评级严 | 看趋势（CK 误差、ITS），不单看 good/fair/poor 标签 |

### 3.3 ColabFold / WSL / Windows 环境（基础设施）

| 问题 | 错误/现象 | 处理 |
| --- | --- | --- |
| 无原生 Windows ColabFold | `colabfold_batch` 找不到 | **WSL2 + LocalColabFold（pixi）** |
| DNS 劫持 | `WININET_E_CANNOT_CONNECT`；`aka.ms` → 198.18.x.x | 关代理/PAC、`netsh winhttp reset proxy`、公网 DNS |
| **VT-d ≠ VT-x** | 用户开 VT-d 但 `VirtualizationFirmwareEnabled: False` | BIOS：**Intel 虚拟化技术（Vanderpool）**；VT-d 可并存 |
| Hyper-V 未就绪 | `HCS_E_HYPERV_NOT_INSTALLED` | DISM 启用虚拟机平台 + WSL；BIOS VT-x；冷启动 |
| `pixi install` 超时 | `nvidia-cudnn-cu12` 下载失败 | **`UV_HTTP_TIMEOUT=600`** 重试 |
| 权重占满 WSL 根分区 | 下载慢、难续传 | **`COLABFOLD_WSL_XDG_CACHE`** 指到 `data/colabfold_xdg_cache` |
| 路径被 `wsl` 吞反斜杠 | `wslpath: E:cursor...` | 规范为 **`E:/...`**（`colabfold_batch_wsl.py`） |
| 长跑无 ETA | 对话 jsonl **不能**当实时监控 | 看终端、`predictions/` 是否出 `.pdb`、进程/WSL 状态 |
| 任务已停但用户不知 | WSL Stopped、无 python、无 `.pdb` | `wsl -l -v`、`tasklist`、检查 `results/colabfold` |

### 3.4 数据与配置

- **公开模板与题序列不完全一致**：homolog CIF 长度校验失败 → `sequence_prior_rejected`。
- **interim 模板误提交**：用 RCSB 中间文件冲榜会改变几何但未必涨分 → 明确「勿用 interim 冲榜」。
- **`document/rull.md` 阶段 1～2 深度不足**：早期完成的是工程闭环与提交包，而非完整「文献→公式→代码」审计链。

## 四、类似项目可沉淀的经验

### 4.1 竞赛 / 评测驱动类

1. **先读懂评分分解再写代码**  
   明确 Base vs Ensemble 权重；避免在「precision 敏感」维度盲目增加低质构象数量。

2. **合规前置**  
   数据来源、序列输入、是否 touch GT 写进检查清单；`agent.log` 与归档快照同步，避免代码审核风险。

3. **本地代理指标 ≠ 线上分**  
   自建 `heavy_atom_clash_proxy`、`pairwise_ca_rmsd` 用于**相对比较**；重大策略必须 **线上 A/B**，并保留 `daima` 与锁版 JSON。

4. **质量门槛默认开启**  
   序列先验：**长度一致 + mean pLDDT 下限**；预览/调试模式与「冲榜配置」在脚本层分离（如 `--fast-preview` 不进入默认打包）。

5. **锁版 + 时间线归档**  
   `configs/*.lock*.json` / `daima/guidang` 作最高分快照；每次可能改分的运行：`generate_submission` 时刻 → `archive_run.py --timestamp`。

### 4.2 科学计算 / MD / MSM 类

1. **冒烟 → 短程 → 正式** 三档参数；MD 先修 **积分步长稳定性** 再追时长。  
2. MSM：**采样不足时先减簇数**，再谈 lag/CK；自动结论仅作辅助，需结合帧数与物理直觉。  
3. **DCD 而非 PDB 轨迹**；报告里写清 `n_frames`、`ck_quality` 与建议 next action。

### 4.3 AI 结构预测集成类

1. **Windows 上 ColabFold**：默认规划 **WSL2 路径**（包装脚本、环境变量、测试 `test_colabfold_batch_wsl.py`）。  
2. **权重与缓存放 Windows 挂载盘**，避免 WSL 根分区满；大下载设 **超时重试**。  
3. **先短题、单题、CPU preview 打通管线**，再全题 MSA GPU；避免把 preview 结构提交评测。  
4. **多工具候选池**：统一目录约定 `results/{tool}/problem_{id}/`，合并脚本支持 `--extra-candidate-root`、`mtime_desc`、`max-prior-per-problem`。

### 4.4 智能体 / 人机协作类

1. **长任务必须可观测**：终端日志、`[DONE]`、产物目录、进程列表；**不要**用历史 chat jsonl 推断剩余时间。  
2. **决策点清单化**：算力档位、是否重跑 MD、是否启用新工具，由人确认后再跑小时级任务。  
3. **Prompt 与 SOP 进仓库**：换 agent/换人仍能按 `readme` §1.4、§9 执行。  
4. **小步 diff + §1.5 表格**：每行记录「改动 / 结论 / 下一步」，避免重复踩坑（如 VT-d、fast-preview、multiplier-only）。

### 4.5 推荐复用清单（新项目 Day 1）

```text
[ ] 读清评分公式与提交 schema（mmCIF 字段级）
[ ] 本地 eval 脚本 + 1 个合法 + 1 个非法样例测试
[ ] generate_submission + archive_run + agent.log 模板
[ ] 公开数据下载与序列长度校验
[ ] 序列预测工具路径（本机 GPU / WSL / 云端）与 pLDDT 门槛
[ ] 锁版 config + daima/guidang 最高分快照
[ ] 线上 A/B 记录表（日期、分数、归档目录、差异摘要）
```

## 五、一句话总结

本项目是 **「竞赛可提交构象系综」+「OpenMM/MSM 科研原型」** 的双轨工程：竞赛侧从 **格式与全原子合规（~0.19→~0.70）** 到 **序列条件多模型先验（~0.717）** 的跃迁，证明 **涨分靠高质量多样构象而非局部调参**；环境侧在 **老 Windows + WSL + ColabFold** 上积累了 DNS/虚拟化/缓存/包装器一整套可复用打法；最大教训是 **低质量 preview 结构一旦进入提交链会大幅掉分**，以及 **必须用线上分数与归档体系验证策略，不能只看本地 proxy**。

## 六、与 AI 协作的核心 Prompt（按场景复制）

> 5. **「readme 规划」默认含义**：竞赛全流程 = §1.4 + §9 SOP；**仅当用户写明「科研线/OpenMM」** 时才指 OpenMM→MSM 章节。
